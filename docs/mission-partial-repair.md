# 미션 생성 중 부분 수정

15개 생성 결과에서 서버 검증을 실패한 후보가 1~5개이면, 정상 후보를 보존하고 실패 후보만 LLM에 수정 요청한다. 사용자 재추천 API는 새 미션 15개를 요청하는 기존 의미를 유지한다. 부분 수정용 프런트엔드 API는 추가하지 않는다.

## 흐름과 적용 범위

1. 목표 설정 완료, 오늘 첫 추천 조회의 일일 생성, 사용자 재추천이 공통 `GoalBasedMissionGenerationService`를 호출한다.
2. 기존 프롬프트·모델·출력 상한 4096으로 15개를 최초 생성한다.
3. 서버 코드가 총 15개/난이도별 5개, 제목 10~25자, 설명 20~30자, 기존 한국어 문법 규칙, 과거 미션과 정확히 같은 제목을 검사한다. 별도 LLM 검사 호출은 없다.
4. 난이도 분포가 유효하고 오류 후보가 1~5개이면 해당 후보의 id·기존 내용·오류와 정상 후보의 제목·난이도를 전달한다. 정상 후보의 설명은 서버에 보관한다.
5. 요청한 id만 포함하는 `patches` JSON을 받는다. id 누락·추가·중복, 정수 범위 초과, 난이도 변경, 정상 후보와 같은 제목 등을 거부한다. 검증 전에는 기존 후보를 변경하지 않는다.
6. 수정 후보를 병합하고 15개 전체에 기존 서버 검증을 다시 적용한다. 남은 오류만 다음 수정 대상으로 보낸다.

JSON/난이도 분포 오류, 오류 후보 6개 이상, 잘못된 패치, API 오류는 남은 시도에서 전체 생성으로 돌아간다. 최초 호출 포함 최대 3회를 공유한다. 기존 최소 위반 fallback과 난이도 분포가 끝내 유효하지 않을 때의 예외 처리를 유지한다. 따라서 최대 시도 후 fallback에는 기존처럼 검증 위반이 남을 수 있다.

서버의 문법 검사는 제한된 규칙 검사다. 의미 중복, 목표 적합성, 실행 방법의 타당성을 완전히 검사하지 않는다. 정상으로 분류한 후보의 의미 품질도 보존되므로 별도 표본 검토가 필요하다.

## 설정과 관측

- `openai.mission.partial-repair-enabled` 기본값은 `true`다. 기존 서버 키를 사용하며 키·모델·DB 스키마 변경이 필요 없다.
- 되돌리려면 `OPENAI_MISSION_PARTIAL_REPAIR_ENABLED=false`를 설정하고 재배포한다. 이때 기존 전체 재생성 흐름을 사용한다.
- `OPENAI_TELEMETRY`의 `promptVersion=mission-partial-repair-v1`을 확인한다. 비활성화하면 `baseline-v1`이다. 같은 operationId 아래 최초·재시도·실패 호출의 비용을 모두 합산한다.
- 최초 생성/일일 생성/재추천의 기능별 원가, 재시도 수, 최종 검증 통과 및 fallback 비중을 같은 기간의 Usage와 비교한다. 호출 로그만으로 사용자에게 전달된 결과의 의미 품질을 판정하지 않는다.

## 검증과 비용 근거

모의 OpenAI 응답으로 최초 요청 유지, 정상 후보 보존, 남은 후보 재수정, 과거 제목 중복과 문법 규칙, 패치 오류·API 오류 후 전체 재생성, 최대 3회, 기존 fallback, 비활성화 옵션, operationId·시도·원가 추적을 확인한다. 전체 단위 테스트 144개가 통과했다. 이번 구현 검증에서는 실제 OpenAI 호출을 추가하지 않았다.

[이전 비용 평가](evaluations/mission-partial-repair-2026-10-11.md)는 인위적인 설명 길이 오류 18쌍에서 재시도 비용 69.9%, 이전 최초 생성 비용을 더한 환산 총원가 41.1% 감소를 관찰했다. 월 운영 절감률을 의미하지 않는다. 실제 실패·과거 목록·의미 품질과 운영 원가의 추적이 다음 단계다.

이전 평가 실행 방법과 고정 시드는 [평가 시점 커밋의 문서](https://github.com/SWPY3/haru-up-back-end-2/blob/b8eed03/docs/mission-retry-feedback.md)와 [고정 시드](https://github.com/SWPY3/haru-up-back-end-2/blob/b8eed03/src/test/resources/evaluation/mission-partial-repair-seeds.json)에 남아 있다. 해당 평가 프로토타입을 운영 코드와 중복해서 포함하지 않는다.
